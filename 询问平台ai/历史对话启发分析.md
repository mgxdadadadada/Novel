## 1. 执行摘要

1. **核心产品不是“一次生成正文”，而是可回查、可编辑、可持续更新的原作记忆系统。** 对话1提出“实体普查→角色→世界/力量→关系/事件→风格”的五轮渐进管线，并要求每条事实带出处与置信度（对话1:63-79、184-210、245）；对话2又把该记忆接到概念、角色、世界观、大纲、章节和连载审校（对话2:303-399、574-607）。这与现有竞品证据 E7/E11/E14/E43 相互印证。
2. **事实、推导、创作建议必须分层。** 对话1明确区分原文事实、角色观点、合理推导和推测（对话1:46-48、224-244、1078-1102），是防止模型“把猜测写成原作设定”的最直接规则。
3. **粒度决定检索质量。** “一条一个原子事实、约 200 字以内、可由多个上层查询组合”比长摘要更适合作为 GraphRAG/向量检索单元（对话1:184-210）。
4. **时间与认知状态是同人场景的关键索引。** 角色档案要求按卷/事件保存状态快照，并记录已知、未知、误认（对话1:108-111、212-220）；时间穿越要区分时间线、保留因果闭环、记录认知—事实错位（对话1:357-373）。
5. **类型自适应比固定六维度更有效。** 对话2的统一底层维度为角色人格、关系、因果/时间线、风格、世界规则、冲突引擎（对话2:89-98）；轻小说优先情感与语言指纹，玄幻优先修炼体系/战力/资源账本，悬疑优先线索链/信息差，历史军事优先战术战略（对话2:100-235）。
6. **创作助手应采用“用户状态分流 + 资产状态机”，而不是强制从零开始。** 模糊脑洞、明确想法、完整大纲、已有章节四条路径分别决定跳过/补齐哪些步骤（对话2:253-399）。
7. **质量控制应前置为可执行门禁。** 角色 OOC 清单、硬约束、章纲字段、伏笔等级、三章轮检/十章批审和去 AI 化指标都可以转成评测规则（对话2:401-487、488-573、574-715）。但这些阈值是平台 AI 提出的创作方法论，不是效果已验证的科学常数。

## 3. 对现有项目设计的具体修正

### 3.1 数据模型：从“档案展示”升级为“证据图 + 创作状态”

现有竞品已验证 `summary + characters + world_settings` 档案（E7），章节、笔记、项目是分离资源（E14/E43）。两份对话提示需要补充以下对象：

```text
source_document / source_span
entity / alias
knowledge_entry (atomic fact)
character_snapshot / knowledge_state
relationship / causal_edge / event
timeline / causal_loop
constraint (canon|extension|uncertain)
style_profile / drift_candidate
outline / foreshadow / chapter_focus
quality_issue / review_run / provenance
```

每个可影响正文的对象至少带：`id`、`project_id`、`source`、`confidence`、`status`、`version`、`created_at`、`updated_at`。推断和反事实不得覆盖事实字段，应作为独立记录并保存推导依据。

### 3.2 检索与 Agent：从“相似度召回”升级为“意图 + 时间 + 认知过滤”

检索请求先识别创作意图（角色行为、能力限制、关系推进、章节衔接、风格模仿、冲突校验），再按原作类型权重分配查询；随后过滤 `timeline_id`、章节范围、角色当前 `knowledge_state`，最后返回原子条目及出处。

**MVP 必做：** 向量/全文混合检索、别名归一、章节范围过滤、证据引用、冲突标记、用户确认后写入。

**后置增强：** 反事实模拟、潜台词识别、关系熵值、情绪波形、StoryFork。E16 已显示后五项在当前竞品 bundle 中无对应关键词；E41 仅是第三方宣传，不能当作已上线事实。

### 3.3 写作工作流：引入可恢复状态机

```text
INTAKE → CLASSIFY_GENRE → RESEARCH_GAP → USER_CONFIRM
→ BUILD_CONCEPT → BUILD_CHARACTERS → BUILD_CONSTRAINTS
→ BUILD_OUTLINE → CHAPTER_CONTEXT_READY → STREAM_GENERATE
→ REVIEW → COMMIT_SNAPSHOT → NEXT
```

状态迁移规则：

- 已有完整大纲：跳过概念初稿，但抽取并保存概念、角色、设定缺口；
- 已有章节：先逆向抽取风格/状态/时间线，再从断点续写；
- 任一阶段缺少证据：生成 `needs_confirmation`，不得静默补写为事实；
- 章节生成中断：保留已生成片段、上下文 manifest 和版本号，支持恢复；
- 资产变更：先扫描受影响对象，展示差异和待确认项，再写入新版本。

这与竞品已有 SSE、停止/恢复、memo、章节资源证据（E11/E13/E14/E43）兼容。

### 3.4 评测与质量门禁：先测可验证指标，再逐步加入主观指标

| 阶段 | 自动门禁 | 证据/标注 |
|---|---|---|
| 解析 | 实体覆盖率、别名合并准确率、条目出处完整率、重复率、冲突召回 | 人工 golden set；输出 `coverage_report` |
| 检索 | Recall@5、MRR、时间线/角色认知过滤准确率 | 固定 query + 证据 ID |
| 生成前 | 章纲字段完整、硬约束命中、角色状态齐全、前章衔接 | manifest 校验 |
| 生成后 | OOC 10 项、硬约束违反、伏笔状态、重复模式、词法 AI 指纹 | 规则扫描 + 人工抽样 |
| 连载 | 三章/十章/每卷任务按阈值触发且可追踪 | `review_run` 日志 |

对话2给出的数值（如每章 15–20 个 scene beats、70% 即时场景、每 10 章配角出场）只能作为**初始可配置策略**，不得宣称已证明能提升质量。

## 4. 类型自适应框架（落地版）

统一保留 D1–D6；分类器输出 `genre`、`confidence` 和维度权重。推荐首版配置：

| 类型 | 第一优先级 | 专属增强字段 | 低权重/按需 |
|---|---|---|---|
| 轻小说/动漫/恋爱 | D1+D2 | 萌/反差、语言指纹、情感阶段、日常/约会场景 | 资源账本、宏观政治 |
| 玄幻/仙侠/奇幻 | D5+D6 | 等级/战力锚点、能力限制、资源账本、势力格局 | 潜台词深挖、日常场景 |
| 都市/现实 | D1+D5 | 职业流程、社会关系、阶层与制度约束 | 超自然战力 |
| 悬疑/推理 | D3+D4 | 线索—伏笔链、嫌疑人知识状态、红鲱鱼、揭示节奏 | 资源成长 |
| 科幻/末世 | D5+D6 | 科技规则、生存资源、伦理困境、生态/灾害约束 | 萌属性 |
| 古代言情/宫斗 | D1+D2 | 礼仪称谓、家族/后宫权力、情感升温、身份秘密 | 数值战力 |
| 历史/军事 | D3+D5 | 年表、兵制、后勤、战术/战略、史实与虚构分层 | 萌属性 |
| 重生/穿越（叠加标签） | 依宿主类型 | 前后时间线、蝴蝶效应、记忆保留、身份替换 | 不应独立替代宿主类型 |

权重只决定研究资源，不删除通用维度；否则容易漏掉跨类型作品中的关键事实。

## 5. MVP 取舍与排期建议

### P0（阻塞闭环）

1. 解析状态机 + 分阶段 JSON 契约；
2. 实体/别名/原子条目/出处/置信度；
3. 角色动态快照与认知状态；
4. 混合检索（意图、别名、章节/时间线过滤）；
5. 项目资产（概念、角色、关系、设定、纲、笔记、章节）及用户确认写入；
6. 章节生成前 manifest、SSE 停止/恢复、生成后快照；
7. 最小一致性审校：硬约束、角色状态、出处覆盖、冲突队列。

### P1（差异化）

1. 类型权重配置与研究预算；
2. 关系/因果图、时间线分支、伏笔状态；
3. 三章/十章/每卷审校任务；
4. 设定变更影响扫描与版本差异；
5. 风格档案和可解释的“去 AI 化”检查。

### P2（验证后再做）

反事实推演、潜台词自动标注、关系熵值、情绪波形、StoryFork/并行宇宙、复杂作者风格模仿。

### 推断

- 这些内容足以作为本项目的**需求启发与离线评测设计输入**，不能直接证明奇境 AI 内部采用同一 pipeline。

- 事实图谱与创作资产分层，能兼容原作复用和项目私有改写。

- 五轮解析在本项目真实 TXT/DOCX/EPUB 上的成本、耗时、覆盖率未测；
- 类型分类器权重、OOC 规则、爽点/节奏阈值对用户留存和文本质量的提升未做 A/B 或人工盲评；

## 8. 结论

两份历史对话最大的启发不是某个 prompt，而是一套**可追溯的原作记忆—创作状态—质量审校闭环**：

```text
原作分阶段解析
→ 原子事实/角色状态/时间线（带出处与置信度）
→ 按类型权重和用户起点生成研究计划
→ 用户确认后写入项目资产
→ 章节生成前读取状态与硬约束
→ 流式生成、审校、快照
→ 三章/十章/每卷复盘并修正资产
```

产品路线应先实现 P0 的证据与状态基础，再用 P1 的类型自适应和一致性能力形成差异化；所有平台 AI 自述、反事实推演和创作阈值均应保持证据分层，经过本项目评测后再升级为产品承诺。
