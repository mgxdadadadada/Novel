第一部分：核心任务定义
角色设定
你是一位「虚构世界档案管理员」。你的工作不是评价这本小说写得好不好，
而是像编纂百科全书一样，把小说中所有可验证的事实提取、分类、归档，
构建一个可供后续创作检索的结构化知识库。

你只记录"文本中明确写了什么"和"文本中可合理推导出什么"。
你不做文学解读、不做主题分析、不做价值判断。
为什么是这个角色定义？因为这决定了智能体的行为边界——它要的是事实精度，不是文学赏析。"五河士道拥有封印精灵灵力的能力"是事实，"五河士道是一个温柔的人"是解读，两者必须分开处理。

目标定义
目标产出：一套结构化知识库，覆盖以下六大类：
1. 世界观与设定（宇宙观、地理、历史、组织、社会规则）
2. 力量体系（灵力、天使、魔术、AST装备、DEM技术）
3. 角色档案（身份、性格、能力、经历、语言特征）
4. 关系网络（角色间的静态关系与动态变化）
5. 事件时间线（按因果链编排的关键事件）
6. 写作风格（原作者的叙事习惯、对话风格、描写偏好）

质量标准：任何一条知识库条目，都必须能追溯到原作中的具体出处。
第二部分：任务执行流程
这是最关键的部分。我不会让智能体"一次性读完全书然后输出"，因为轻小说的信息密度不均匀、叙事经常非线性，一次性处理会丢失大量边缘信息。

我会设计一个五轮渐进式提取流程：

第一轮：实体普查（通读全文，建立实体索引）
任务：通读全书，识别并记录所有"可命名实体"。
不要提取详细信息，只建立索引清单。

实体类型包括：
- 人物（包括分身、过去/未来版本、化名身份）
- 地点（城市、建筑、空间、异空间）
- 组织与势力
- 物品与道具（灵结晶、天使、灵装、魔术装置）
- 能力与术式
- 事件名称（天宫市火灾、天央祭事件等）
- 概念术语（空间震、反转、封印状态等）

输出：每个实体分配唯一ID，记录首次出场卷/章，标注实体类型。
为什么第一步只做索引？因为先建立目录再深入，可以防止后续轮次遗漏实体。很多配角、一次性出现的地点、某个术式的名称，如果不在第一轮扫描到，后面就永远丢失了。

第二轮：角色深度提取（为每个角色建立完整档案）
任务：基于第一轮的人物索引，逐角色提取以下维度的信息：

A. 基础身份
   - 全名、别名、代号、外号
   - 种族/身份（人类/精灵/巫师后裔/分身等）
   - 所属组织（含组织内角色/职位）
   - 外貌特征（原作中的关键描写，不添加主观修饰）

B. 能力体系
   - 天使/魔术名称、形态、能力描述
   - 灵装描述
   - 特殊体质或天赋
   - 能力的限制条件与代价
   - 能力在故事中的变化/进化

C. 性格与行为模式
   - 性格关键词（从原作行为中归纳，而非直接贴标签）
   - 语言特征（口头禅、敬语习惯、说真话的方式）
   - 关键行为模式（面对威胁时的典型反应、独处时的习惯）
   - 情感触发点（什么情况下会失控、动怒、流泪、展露真心）

D. 经历概要
   - 出生/起源背景
   - 关键转折事件（按时间线排列）
   - 故事结束时的状态

E. 认知状态快照（重要！）
   - 该角色对各关键事件的"已知/未知/错误认知"
   - 例：在某一卷，折纸知道杀死她父母的是炎之精灵，但不知道那是琴里
这里最有意思的是E.认知状态快照。对于《约会大作战》这种有时间穿越和信息不对称的作品，角色在不同时间点知道什么、不知道什么、误以为什么，是写同人时最容易出错的地方。这个维度必须单独建模。

第三轮：世界观与力量体系提取
任务：提取所有"世界运行规则"层面的信息。

A. 宏观世界观
   - 精灵的起源（初始精灵创造过程）
   - 两个世界（邻界与现实世界）的关系
   - 空间震的成因与机制
   - 世界的时间线框架

B. 力量体系
   - 灵力的本质、来源、流转规则
   - 天使体系（名称、分类、能力规则）
   - 灵结晶机制（植入、抽取、反转条件）
   - 精灵状态（正常/封印/反转/天使化）
   - 魔术体系（DEM/AST的技术与术式分类）

C. 组织档案
   - 拉塔托斯克（结构、设施、关键成员、行事方针）
   - DEM（结构、势力范围、关键技术、内部派系）
   - AST/SSS（编制、装备、指挥链）
   - 其他势力

D. 地理与空间
   - 天宫市结构（关键地点及其功能）
   - 拉塔托斯克空中舰
   - DEM设施分布
   - 邻界描述

E. 规则硬约束
   - 哪些设定是"绝对规则"不可违反
   - 哪些设定存在模糊地带或扩展空间
第四轮：关系网络与事件因果链
任务：在前三轮基础上，构建关系网络和事件链。

A. 角色关系对
   - 为每对有交集的角色建立关系条目
   - 记录关系的起点、关键转折、当前状态
   - 标注关系中的张力来源（信任/怀疑/利用/保护）

B. 事件因果链
   - 为每个关键事件记录：触发条件、过程、结果、后续影响

   - 特别标注"反事实"节点（如果这个事件没有发生，后续会完全不同）

C. 时间线

关键设计决策：为什么是"200字以内为一条"？
这是我最想强调的一条规则。很多系统会把一整段原文直接塞进一条知识库，结果是信息粒度太粗，检索时命中但无用。

反例（一条塞太多）：
"狂三拥有刻刻帝，是一把巨大的时钟型天使，可以通过不同数字
对应的时间能力进行攻击和操控，包括加速自身、减速敌人、穿越
时间、制造分身等，使用能力需要消耗'时间'即自身寿命。"

应拆分为：
- 条目1：刻刻帝-形态 [时钟型天使，双枪为其化身]
- 条目2：刻刻帝-能力总览 [12个数字对应12种时间能力]
- 条目3：刻刻帝-四之弹 [使目标时间倒流，用于复活分身]
- 条目4：刻刻帝-八之弹 [召唤过去的自己的分身]
- 条目5：刻刻帝-十二之弹 [将施术者送往过去，需巨大时间消耗]
- 条目6：刻刻帝-代价 [使用能力需消耗'时间'即自身寿命]
每条只包含一个原子级事实，检索时精确命中，也可以被多个上层查询组合引用。

核心困难
虚构叙事中的因果关系有三个陷阱：

第一，时序不等于因果。 "十香转学→士道封印十香"，这两个事件有时序关系，但真正的因果链是"十香出现→拉塔托斯克发现士道的封印能力→琴里决定让士道与精灵约会→士道尝试了解十香→十香对士道打开心扉→封印成功"。如果只标记时序关系，因果链就断了。

第二，原作经常隐藏因果。 第三卷里狂三虐杀人类是"事件"，但她为什么虐杀人类？原作直到第十六卷才揭示"她需要吞噬时间来发动十二之弹"，而十二之弹的目的又是更后面才揭示的。一个在第三卷提取因果链的智能体，如果不考虑后续信息，会把狂三的行为归因为"她就是邪恶的"，这是一个错误的因果推断。

第三，时间穿越制造因果悖论。 折纸的父母是被穿越回去的折纸自己误杀的。那么"折纸父母的死"的原因是什么？是折纸的穿越，但折纸穿越的原因又是父母的死。这是一个因果闭环，不能简单标记为"A→B"。

具体指令设计
我会给智能体下达以下规则集：

规则一：因果关系的判定标准
不是所有"先发生→后发生"的关系都是因果关系。
只有满足以下至少一个条件时，才标记为因果链接：

条件A — 替代测试：如果事件X没有发生，事件Y在原作设定下
         是否大概率不会发生？
         → 是，则X是Y的必要条件，标记为 [X →(必要) Y]

条件B — 叙事信号：原作者在叙事中是否通过以下方式暗示了因果？
         - 角色明确说出"因为X所以Y"
         - 叙述者用因果连接词描述两个事件
         - 事件X之后，叙事节奏刻意加快/聚焦，暗示X触发了连锁反应
         → 是，标记为 [X →(暗示) Y]，置信度低于"必要"

条件C — 动机链：事件X是否为角色提供了执行行动Y的动机或手段？
         → 是，标记为 [X →(动机) Y]

不符合以上任何条件的时序关系，标记为 [X →(时序) Y]，
不归入因果链。
为什么要这样分？因为不同类型因果链接的可靠性不同。写同人时，你可以无视"时序"关系自由调整情节，但不能无视"必要"关系——否则会产生逻辑断裂。

规则二：因果链的提取流程
对每个关键事件，执行以下步骤：

步骤1 — 识别触发条件
  "这个事件为什么会发生？追溯到直接触发它的前一个事件。"
  输出：触发事件ID + 触发类型（必要/暗示/动机/时序）

步骤2 — 识别促成因素
  "除了直接触发事件，还有哪些更早的事件为它创造了条件？"
  输出：促成事件ID列表，每个标注贡献类型
  例：琴里变成精灵 ← 澄将灵结晶分散（必要条件）
               ← 五河家收养了士道（促成条件，非必要）

步骤3 — 识别直接后果
  "这个事件直接导致了什么？"
  输出：后果事件ID + 影响描述

步骤4 — 识别延迟后果
  "这个事件在后续数卷中有没有产生连锁影响？"
  输出：延迟后果事件ID + 延迟距离（隔了几卷）

步骤5 — 反事实测试（仅对"必要"和"动机"类型执行）
  "假设这个事件没有发生，标记受影响的下游事件，
   以及叙事可能的替代走向。"
  输出：反事实假设 → 受影响事件列表 → 替代走向推测（标注为推测）
规则三：反事实节点的判定指令
这是你最关心的部分。我会这样写：

「反事实节点」的定义：
一个事件E被标记为「反事实节点」，当且仅当——
在原作叙事中，存在以下任意一种信号：

信号1 — 叙事分叉暗示
  原作中角色或叙述者明确提到"如果当时没有……"或"假如……的话"。
  例：士道在第四卷回忆道"如果那天我没有冲进空间震灾区，
  就不会遇见十香，也不会知道精灵的存在"。
  → 「士道冲入空间震灾区」标记为反事实节点。

信号2 — 作者刻意铺垫的"几乎没发生"
  原作用大量篇幅描写一个事件差一点没有发生——
  角色犹豫、外部干扰、巧合促成。
  这种描写本身暗示作者认为"这个事件的发生不是必然的"。
  例：士道差一点就来不及封印琴里，只剩最后两天。
  → 「士道在截止日前封印琴里」标记为反事实节点。

信号3 — 因果链中的唯一路径
  当一个事件的结果在因果链中只有一个上游原因，
  且这个原因是可变的（不是世界规则的必然结果），
  则这个原因标记为反事实节点。
  例：折纸反转的原因唯一指向"她发现是自己杀了父母"。
  如果她没有穿越回去，就不会反转。
  → 「折纸穿越回五年前」标记为反事实节点。

信号4 — 时间穿越创造的因果闭环
  当事件A导致了事件B，而事件B又通过时间穿越导致了事件A，
  则A和B共同标记为「因果闭环」。
  例：折纸父母被杀 → 折纸穿越回去 → 折纸误杀父母
  → 标记为「因果闭环-折纸事件」。

  "置信度": "高/中/低",
  "信号来源": "信号1/信号2/信号3/信号4"
}
规则四：处理时间穿越的特殊规则
对于包含时间穿越的叙事，因果链提取必须额外执行：

1. 区分「原时间线」和「修改后时间线」
   每个时间穿越事件后，标记一条新的时间线分支。
   原时间线的事件不被覆盖，但标注"在修改后时间线中此事件已被消除"。

2. 因果闭环不拆解，整体标注
   不要试图在闭环中找到"最初原因"——它不存在。
   将整个闭环作为一个特殊条目处理，
   标注其内部因果关系和闭环结构。

3. 标注"认知-事实错位"
   在时间穿越发生后，角色对事件的记忆可能和实际发生不符。
   这种错位必须单独标注——因为它直接影响同人创作中的角色行为。
   例：修改后时间线中的折纸不记得自己曾是精灵，
   但士道记得。

一个诚实的局限
我必须承认一件事：即使给了这些规则，AI做反事实分析仍然存在一个根本性的短板——它无法真正"模拟"另一个世界线。它做的本质上是"在原文中寻找作者暗示了因果关系的叙事信号"，然后基于这些信号做合理的逻辑延伸。它不能像人类读者那样凭直觉想象"如果十香没有遇到士道会怎样"。

所以最后我会加一条元规则：

所有反事实推测必须标注为「推测」，置信度不高于「中」。
这条知识库的用途是为同人创作者提供参考，而非充当权威裁定。
创作者有权在理解原作因果链的基础上，选择打破某条因果关系
——但前提是他们知道自己在打破什么。
知识库的价值不是"告诉你必须怎么写"，而是"告诉你原作是怎么构建的，这样你在改写时知道自己改了什么"。

类别D：地点/空间（LOC）
判定条件：
- 是角色活动发生的具体空间
- 拥有专有名称，或虽然没有专有名称但承担了重要叙事功能
- 包括现实地点和异空间

类别E：事件（EVT）
判定条件：
- 是在特定时间点发生的、可明确界定起止的具体事件

- 不属于以上五类，但对理解世界观不可或缺
- 通常是"理解其他实体的前提条件"

  a) 角色的伪装身份与真实身份（如"士道"和女装"士织"

规则4 — 归一化记录
  每次归一化操作必须记录：
  - 主名（选择的正式名称）
  - 别名列表（所有替代称呼）
  - 每个别名首次出现的位置
  - 归一化的依据（规则2的哪一条）

2.2 认知状态快照的判定规则
这是你最关心的部分。判定一个角色"在某时间点知道什么"，我设计以下规则：

认知来源追溯规则：

规则1 — 直接感知优先
  如果角色在某场景中"亲眼看见"、"亲耳听见"、"亲身经历"了某事，
  则在该场景时间点之后，标记该信息为"已知"。

规则2 — 对话传递追踪
  如果角色A在对话中告诉角色B某事，则B在对话结束后标记"已知"。
  附加条件：需确认B是否在该对话中真的"听到"了——
  如果B当时昏迷、走神、被中断，则标记为"可能未接收"。

规则3 — 推理标记
  如果角色通过已有信息做出了正确推理（原文中角色的心理活动
  明确展示了推理过程），则标记"已知（推理）"，置信度降一级。
  如果原文没有展示推理过程，但角色行为表明他知道了某事，
  标记"已知（行为推导）"，置信度再降一级。

规则4 — 错误认知检测
  当角色表达了一个判断（对话或心理活动），而读者已知的事实
  与之不符时，标记为"错误认知"。
  检测方法：将角色的认知条目与"全局事实条目"交叉比对，
  不一致的标记为⚠。

规则5 — 时间穿越的认知特殊处理
  时间穿越后，穿越者的认知包含"原时间线的记忆"，
  但周围角色没有这些记忆。
  需要为每个角色维护"当前时间线"和"跨时间线记忆"两个认知层。
第三部分：世界观条目的原子化切分规则
3.1 切分判定规则
核心原则：一条知识库条目只包含一个"可独立理解的事实原子"。

判定方法——「删除测试」：
  假设把条目X从知识库中删除。
  如果删除后，读者仍然能完全理解其他所有条目，
  则X是独立的原子条目，切分正确。
  如果删除后，某条目Y变得无法理解（因为Y依赖X的信息），
  则X和Y应该合并，或者建立显式的依赖关系。

辅助判定——「问答测试」：
  如果一个条目可以被一个独立的问题完整回答，则是原子条目。
  如："空间震是什么？"→可以被一条条目完整回答→是原子条目。
  如："空间震是什么、怎么发生的、有多大、谁引发的？"→
  这是四个问题→应拆为四条。

切分的粒度标准：
  - 过粗（一条包含多个事实）→ 检索命中但不精确
  - 过细（一条只包含半句话）→ 丢失上下文，无法独立理解
  - 合适（一条 = 一个完整的事实陈述 + 必要的上下文）→ 目标
实例 — 空间震的设定切分：

原文段落：

"空间震是原因不明的广域灾害。三十年前首次发生在欧亚大陆中心，
造成一亿五千万人死亡。日本建立了完善的预警和避难系统。
五年前天宫市再次开始频繁发生空间震。"

错误切分（过粗）：

❌ 一条："空间震是原因不明的广域灾害，三十年前首次发生，
死亡一亿五千万人，日本有避难系统，五年前天宫市频繁发生。"
问题：包含了5个独立事实，检索时无法精确定位

错误切分（过细）：

❌ "空间震是灾害" + "空间震原因不明" + "空间震是广域的"
问题：拆散了语义完整性，三条单独看都无法独立理解

正确切分：

✅ CON-001："空间震——精灵从邻界来到现实世界时产生的
广域爆炸震动。表现形式为耀眼光芒+冲击波+地表被削成钵状凹洞。
破坏规模从数公尺到大陆级不等。"
（一条条目，原子级事实，但保留了完整的定义）

✅ EVT-001："欧亚大空灾——三十年前发生在欧亚大陆中心的
首次大规模空间震，死亡一亿五千万人，大陆中心区域被完全抹除。"
（独立事件条目，与CON-001关联）

✅ CON-002："空间震避难系统——日本在欧亚大空灾后建立的
预警与避难机制，包括警报、广播通知、地下避难所，
灾后由灾害复兴部队修复城市。"
（独立概念条目，与CON-001关联）

✅ EVT-002："天宫市空间震频发——五年前起天宫市开始频繁
发生空间震，近年频率持续升高，原因与精灵现界有关。"
（独立事件条目，与CON-001和LOC-天宫市关联）

3.2 上下文关联保护规则
规则1 — 关联字段必须填写
  切分后的每条条目，必须在"关联条目"字段中列出：
  a) 前置依赖条目（不读它就无法理解本条的条目）
  b) 后续延伸条目（读完本条后可能需要继续查看的条目）
  c) 同主题的并列条目

规则2 — 上下文锚点
  当一条条目必须引用原文的叙述顺序才能正确理解时，
  在"备注"字段标注"上下文锚点"：
  "此条目的含义依赖于其在原文中的位置——在[具体上下文]中
  出现，与[前文/后文]形成[对比/递进/转折]关系。"

规则3 — 不可切分的例外
  以下情况不进行切分，保持为单一粗条目：
  a) 定义性描述（"X是指……"的句子，拆开后定义不完整）
  b) 因果对（"A导致B"，拆成"A是原因"和"B是结果"会丢失因果）
  c) 对比描述（"X不同于Y……"，拆开后对比关系丢失）
3.3 层级关系标注规则
父子关系判定：

类型1 — 整体/部分关系
  父条目：来禅高中
  子条目：来禅高中-二年四班、来禅高中-食堂、来禅高中-屋顶
  规则：子条目在物理或逻辑上属于父条目

类型2 — 上位/下位关系
  父条目：显现装置
  子条目：CR-Unit、随意领域、穿著型接续装置
  规则：子条目是父条目概念的具体实例或组件

类型3 — 体系/成员关系
  父条目：十香的能力体系
  子条目：鏖杀公、神威灵装·十番
  规则：子条目是该体系下的具体能力/装备

类型4 — 总述/分述关系
  父条目：空间震
  子条目：欧亚大空灾、南关东大空灾、天宫市频发事件
  规则：父条目是总概念，子条目是具体事件实例

输出格式：
{
  "条目ID": "LOC-003",
  "名称": "来禅高中-二年四班",
  "父条目": "LOC-001-来禅高中",
  "层级关系": "整体/部分"
}
第四部分：写作风格的具体提取规则
4.1 叙事距离的量化方法
定义：叙事距离 = 叙述者与角色内心世界的接近程度
距离越近，读者越能感受到角色的想法和感受；
距离越远，叙述越像客观记录。

测量方法——基于三个维度的评分：

维度1：心理描写密度
  统计方法：在每1000字的叙事文本中，计算角色内心活动
  （想法、感受、情绪描写）所占的字数比例。
  - 比例 > 30% → 极近距离（意识流级别）
  - 比例 15%-30% → 近距离（贴近角色内心）
  - 比例 5%-15% → 中距离（偶尔进入内心）
  - 比例 < 5% → 远距离（几乎纯客观叙述）

维度2：感知锁定程度
  判定：叙述是否严格局限于POV角色的五感？
  - 严格锁定：只写POV角色看到、听到、闻到、触到、想到的
  - 大部分锁定：偶尔出现POV角色不可能知道的信息
  - 松散锁定：频繁出现全知视角信息

维度3：语言风格贴近度
  判定：叙述者的用词、句式是否贴近POV角色的语言习惯？
  - 高度贴近：叙述语气和角色口语风格一致
  - 部分贴近：叙述比角色口语更文学化，但保留部分口吻
  - 完全独立：叙述者有自己的语言风格，与角色无关
实例 — 《约会大作战》第1卷第1章叙事距离分析：

维度1 测量（晨间场景约3000字）：
  士道心理活动字数：约600字（"从士道的位置望去"的观察、
  对琴里行为的吐槽、对时间的判断等）
  比例 ≈ 20% → 近距离

维度2 测量：
  严格锁定——第一章全程只写士道能看到、听到、想到的内容
  例：折纸为什么认识士道，叙述者没有给出答案，
  因为士道自己也不知道 → 严格POV锁定
  例外：序章中对十香外貌的描写过于详细，部分超出了士道
  在紧张状态下的观察极限，属于"文学化处理"而非真正的POV泄露
  → 判定：大部分锁定

维度3 测量：
  叙述者的吐槽语气与士道高度一致
  例："除了少数拥有特殊喜好的人类以外，大部分的人应该都会
  因此而感到不悦吧？"——这种自嘲式吐槽就是士道的声音
  → 判定：高度贴近

综合判定：《约会大作战》第1卷 = 近距离受限第三人称
  叙事距离评分：近（贴近主角内心，但不使用意识流）
4.2 潜台词使用的识别规则
定义：潜台词 = 角色说出的话与角色真正想表达的意思不一致，
读者需要"解码"才能理解真实含义。

识别判定标准——以下任一条件成立即标记为潜台词：

条件A — 言行不一致
  角色说的话和角色的行为/表情/生理反应矛盾。
  例：角色说"我不在意"，但叙述描写"握紧了拳头"。

条件B — 语境不匹配
  角色的回应和问题/场景不构成字面上的逻辑关系，
  暗示角色在回避或转移话题。
  例：士道问折纸"你为什么认识我"，折纸回答"你不记得了吗？"
  → 字面上没有回答问题，实际在暗示"我们以前见过"。

条件C — 叙述者暗示
  叙述者在角色对话后加入的描写，暗示了对话的隐藏含义。
  例：琴里讨论空间震时"突然含糊其辞"——
  叙述者用这个描写暗示琴里知道的比说出来的多。

条件D — 读者的信息优势
  读者通过前文已经知道的信息，可以判断角色的话是假话或误导。
  需要标注"读者需要什么前置信息才能识别此处潜台词"。

输出格式：
{
  "位置": "第1卷第1章，琴里讨论空间震的对话",
  "表面文本": "琴里的讨论内容",
  "潜台词判定": "条件C——叙述者暗示",
  "隐藏含义": "琴里对空间震的真实了解程度远超普通国中生",
  "识别所需前置信息": "无（叙述者的暗示在当下即可察觉）",
  "后续验证": "第2卷暴露琴里是拉塔托斯克司令官"
}
实例 — 第1卷第1章的潜台词清单：

位置	表面文本	条件	隐藏含义
折纸搭话	"你不记得了吗？"	B-语境不匹配	我们以前见过，但你不记得了；暗示士道和折纸有过去
琴里讨论空间震	讨论中含糊其辞	C-叙述者暗示	琴里知道的比普通国中生多得多
折纸随后沉默	不再回应士道的追问	A-言行不一致	主动搭话却不解释→她有目的但不想透露
4.3 前后矛盾/设定漂移的检测规则
检测方法——三层扫描：

第一层：硬事实矛盾
  同一事实被给出了两个不兼容的描述。
  检测方式：
  a) 建立"事实条目"的版本历史——当同一事实出现新的描述时，
     自动比对是否与已有版本矛盾
  b) 矛盾判定标准：两个描述不能同时为真
  c) 输出：矛盾双方的原文引用+出处卷章

  例：某卷说"空间震三十年前首次发生"，另一卷说"空间震
  在远古时代就有记录"→ 硬事实矛盾

第二层：数值/时间线矛盾
  年龄、日期、数量、时间间隔等数值型信息前后不一致。
  检测方式：
  a) 建立角色年龄的时间线追踪（每卷开始时的年龄）
  b) 自动计算事件间隔与角色描述是否吻合
  c) 检测"X年前发生的事件"在不同卷中的X值是否一致

  例：第1卷说"五年前天宫市开始频繁发生空间震"，
  第3卷说"三年前天宫市空间震频发"→如果两卷之间故事
  时间只过了不到一年，则存在数值矛盾

第三层：设定漂移（最隐蔽）
  同一设定在不同卷中的表现不一致，但不是直接矛盾，
  而是"规则被悄悄修改了"。
  检测方式：
  a) 为每个核心设定建立"规则条目"（如：封印精灵需要接吻）
  b) 当后续卷中出现了与此规则不完全一致的行为时，
     自动标注"可能的设定漂移"
  c) 需要人工判断是"真正的漂移"还是"规则有未说明的例外"

  例：早期设定"封印必须通过接吻"，但后续某处出现了
  不通过接吻就完成封印的场景→标注"设定漂移候选"

输出格式：
{
  "矛盾类型": "硬事实矛盾/数值矛盾/设定漂移",
  "条目A": { "内容": "...", "出处": "第X卷第X章" },
  "条目B": { "内容": "...", "出处": "第Y卷第Y章" },
  "矛盾描述": "A说X，B说Y，二者不能同时为真",
  "严重程度": "高/中/低",
  "处理建议": "保留A/保留B/标注为原作不一致/需要人工判断"
}
第五部分：质量控制规则
5.1 置信度标注通用标准
三级置信度标准：

等级1 — 明确记载 [置信度：高]
  判定条件：原文中有直接、完整的陈述
  包括：
  - 叙述者的直接陈述（"空间震是广域灾害"）
  - 角色的完整自述（"我叫五河琴里"）
  - 原文中有明确数字/日期/名称

等级2 — 合理推导 [置信度：中]
  判定条件：原文没有直接陈述，但从已知信息中可以逻辑推导
  包括：
  - 从角色行为推导性格（折纸不笑→"不善于表达情感"）
  - 从时间线推导年龄（高中生→约16岁）
  - 从上下文推导关系（琴里叫士道"哥哥"→兄妹关系）
  注意：必须在条目中注明"推导依据"，不能隐藏推导过程

等级3 — 存疑/推测 [置信度：低]
  判定条件：原文信息不足以确认，需要假设
  包括：
  - 对角色动机的推测（"折纸可能因为……所以……"）
  - 对未揭示信息的猜测（"琴里的父母可能……"）
  - 原文存在多种合理解读的情况
  注意：此等级条目必须明确标注"推测"，不得与事实条目混同
5.2 去重合并规则
场景：同一实体被多轮提取，或在同一轮中从不同上下文中被重复提取。

去重流程：

步骤1 — ID匹配
  如果两次提取的条目ID相同（归一化后），直接合并。
  合并策略：取两次提取的信息的并集，矛盾处标注"需人工判断"。

步骤2 — 名称模糊匹配
  如果ID不同但名称高度相似（如"来禅高中"vs"都立来禅高中"），
  进入人工确认流程。自动判定规则：
  - 编辑距离 < 3 且属于同一类别 → 大概率是同一实体，自动合并
  - 编辑距离 >= 3 → 不自动合并，标注"疑似重复，请确认"

步骤3 — 跨类别去重
  同一文本片段在不同轮次被分到不同类别时（如"佛拉克西纳斯"
  第一轮识别为LOC，第三轮识别为ORG的一部分），
  保留两个条目但建立交叉引用，不强制合并。

合并后的信息来源标注：
  每条信息都保留其原始来源卷章，合并后不丢失出处。
5.3 矛盾检测与处理
检测流程：

步骤1 — 自动比对
  每次新条目入库时，与已有条目做以下比对：
  a) 同实体的同类条目 → 检查是否存在硬事实矛盾
  b) 涉及时间线的条目 → 检查时间数值是否自洽
  c) 涉及因果的条目 → 检查因果链是否形成不可能的循环

步骤2 — 矛盾分类
  A类：明确矛盾（两个描述不能同时为真）
  B类：模糊矛盾（可能矛盾，但可能有未说明的解释）
  C类：版本矛盾（可能是原作不一致，而非知识库错误）

步骤3 — 处理策略
  A类：两条条目均标记"⚠矛盾待处理"，暂停入库，提交人工审核
  B类：两条条目均标注"可能存在矛盾"，允许入库但添加警告标记
  C类：两条条目均保留，各自标注"原作在不同卷中表述不同"，
       并记录两个版本的原文出处，供使用者自行选择

6.2 异常处理规则
异常1：某轮提取结果不完整
  触发条件：某实体在某轮中未被成功提取
  处理：
  a) 自动检测——对比实体索引与各轮输出的覆盖列表，
     未覆盖的实体标记为"遗漏候选"
  b) 对遗漏实体重新执行该轮的提取逻辑
  c) 如果两次提取均失败，标记为"需人工补充"

异常2：条目质量不达标
  触发条件：条目内容少于20字、置信度为"低"且无推导依据
  处理：返回该条目重新处理，附加"请补充原文引用"的指令

异常3：轮次间信息冲突
  触发条件：轮次2的角色档案与轮次3的世界观条目对同一事实
  给出了不同描述
  处理：进入矛盾检测流程（见5.3），自动分类并报告

异常4：跨卷信息不一致
  触发条件：同一事实在不同卷中有不同描述
  处理：保留所有版本，标注"原作多版本"，记录每个版本的出处

function BuildKnowledgeBase(novel_text):

  // ========== 轮次1：实体普查 ==========
  entity_index = {}
  FOR chapter IN novel_text.chapters:
    entities = ExtractEntities(chapter)  // 应用1.1判定条件
    FOR entity IN entities:
      classified = ClassifyEntity(entity)  // 应用1.2分类规则
      normalized = NormalizeAlias(entity, entity_index)  // 应用1.3归一化
      IF normalized.is_new:
        entity_index.add(normalized.canonical_id, normalized)
      ELSE:
        entity_index[normalized.canonical_id].merge(normalized)

  // ========== 轮次2：角色档案 ==========
  character_profiles = {}
  FOR entity IN entity_index.filter(category="CHR"):
    profile = {
      "identity": ExtractIdentity(entity, novel_text),
      "appearance": ExtractAppearance(entity, novel_text),
      "abilities": ExtractAbilities(entity, novel_text, entity_index),
      "personality": ExtractPersonality(entity, novel_text),
      "cognitive_snapshots": {}
    }
    // 认知状态快照——为每个关键时间点生成
    FOR timepoint IN GetKeyTimepoints(entity, novel_text):
      snapshot = ExtractCognitiveState(entity, timepoint, novel_text)
      profile.cognitive_snapshots[timepoint] = snapshot
    character_profiles[entity.id] = profile

  // ========== 轮次3：世界观条目 ==========
  worldview_entries = {}
  FOR entity IN entity_index.filter(category != "CHR"):
    raw_content = ExtractContent(entity, novel_text)
    // 原子化切分
    atoms = AtomicSplit(raw_content)  // 应用3.1切分规则
    FOR atom IN atoms:
      entry = {
        "id": GenerateID(atom),
        "content": atom,
        "source": atom.source_location,
        "confidence": AssessConfidence(atom),  // 应用5.1
        "parent": DetermineHierarchy(atom, worldview_entries),  // 应用3.3
        "related": FindRelated(atom, worldview_entries, character_profiles)
      }
      // 去重检查
      duplicate = CheckDuplicate(entry, worldview_entries)  // 应用5.2
      IF duplicate:
        worldview_entries[duplicate.id].merge(entry)
      ELSE:
        worldview_entries[entry.id] = entry

  // ========== 轮次4：关系与事件链 ==========
  relationships = []
  FOR pair IN Combinations(character_profiles, 2):
    rel = ExtractRelationship(pair.a, pair.b, novel_text)
    IF rel: relationships.add(rel)

  events = {}
  FOR entry IN worldview_entries.filter(category="EVT"):
    event = {
      "causes": TraceCauses(entry, novel_text),  // 应用因果规则
      "effects": TraceEffects(entry, novel_text),
      "counterfactual": TestCounterfactual(entry, novel_text)  // 应用反事实规则
    }
    events[entry.id] = event

  timeline = BuildTimeline(events)

  // ========== 轮次5：写作风格 ==========
  style_profile = {
    "narrative_distance": MeasureNarrativeDistance(novel_text),
    "subtext": DetectSubtext(novel_text),
    "setting_drift": DetectSettingDrift(worldview_entries, novel_text)
  }

  // ========== 质量审核 ==========
  all_entries = Merge(character_profiles, worldview_entries, relationships, events)
  contradictions = GlobalContradictionCheck(all_entries)  // 应用5.3
  coverage = CoverageCheck(entity_index, all_entries)  // 检查遗漏
  quality_report = GenerateQualityReport(contradictions, coverage)

  // ========== 输出 ==========
  RETURN {
    "entity_index": entity_index,
    "character_profiles": character_profiles,
    "worldview_entries": worldview_entries,
    "relationships": relationships,
    "events": events,
    "timeline": timeline,
    "style_profile": style_profile,
    "quality_report": quality_report
  }
